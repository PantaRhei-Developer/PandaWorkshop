# XAI入門 — 「なぜAIはそう判断したのか」を説明する技術

## 1. はじめに

こんにちは。PantaRhei のデータ部に所属しているきょうへいです。
最近では社内案件を担当しています。

AIを業務に組み込もうとすると、精度の次に必ず聞かれる質問があります。

「で、AIは **なぜ** そう判断したの？」

たとえば、AIが「この取引先は与信リスクが高い」と判定したとします。精度がどれだけ高くても、理由がわからなければ、担当者は上司に説明できませんし、取引先から問い合わせがあっても答えられません。結局「AIの結果は参考程度に」となり、業務で使われなくなってしまいます。

この問題に取り組むのが **XAI（Explainable AI：説明可能なAI）** です。

この記事では、XAIとは何か、なぜ今重要なのか、代表的な手法とユースケース、そして使うときの注意点を紹介します。

## 2. XAIとは何か

### ブラックボックス問題

決定木や線形回帰のようなシンプルなモデルであれば、「年収が〇〇以上なら承認」のように、判断の根拠を人間が直接読み取れます。

一方、ディープラーニングや勾配ブースティングのような高精度なモデルは、内部で膨大なパラメータが複雑に絡み合っており、人間が見ても判断の理由がわかりません。これを **ブラックボックス問題** と呼びます。

一般に、モデルは精度が高くなるほど中身が読み取りにくくなる傾向があります。

### XAI：判断の根拠を人間にわかる形で示す

XAIは、AIの判断の根拠を人間が理解できる形で示すための技術・考え方の総称です。

XAIの手法は、大きく次の2つの軸で整理できます。

| 軸 | 種類 | 意味 | 例 |
|---|---|---|---|
| **説明の範囲** | 大域的（Global） | モデル全体として、何を重視しているか | 「このモデルは全体として"年収"を最も重視している」 |
| | 局所的（Local） | ある1件の判断について、何が効いたか | 「Aさんが否決されたのは"延滞履歴"の影響が大きい」 |
| **説明のタイミング** | モデル自体が解釈可能 | 最初から中身が読めるモデルを使う | 決定木、線形回帰、ルールベース |
| | 事後的（Post-hoc） | 学習済みのブラックボックスモデルを後から分析する | SHAP、LIME、Grad-CAM |

実務では、**精度の高いモデルを使いつつ、事後的な手法で説明を付ける** という組み合わせがよく使われます。

## 3. なぜ今XAIなのか

### 3-1. AIの判断が、人の生活やお金に直接関わるようになった

AIは、与信審査、採用、保険の引き受け、医療診断の支援など、人の生活や財産に直接影響する場面で使われるようになっています。

こうした場面では、「AIがそう言ったから」では済みません。判断を受けた本人に対して、**なぜその結果になったのかを説明する責任** が生じます。

### 3-2. 規制・ガイドラインで「説明」が求められ始めている

各国でAIに関するルール作りが進んでいます。

- **EU AI Act**：与信審査や採用などを「高リスクAI」に分類し、透明性や人間による監督を求めている（段階的に適用）
- **日本**：AI事業者ガイドラインで、透明性やアカウンタビリティ（説明責任）が重要な原則として示されている

「説明できないAIは使えない」という場面は、今後さらに増えていくと考えられます。

### 3-3. モデルの「ズル」を見つけられる

XAIは、説明のためだけでなく、**モデルの品質チェック** にも役立ちます。

有名な例に、「狼とハスキー犬を見分ける画像分類モデル」があります。精度は高かったのですが、XAIで判断の根拠を可視化してみると、モデルは動物ではなく **背景の雪** を見て「狼」と判定していました。学習データの狼の写真に、たまたま雪が多く写っていたためです。

精度の数字だけを見ていると、こうした問題には気づけません。モデルが **正しい理由で正しく判断しているか** を確認できるのがXAIの強みです。

### 3-4. LLM・AIエージェントの時代にも重要性が増している

LLMやAIエージェントが業務を実行するようになると、「なぜその回答をしたのか」「なぜその操作を実行したのか」を確認する必要性はさらに高まります。

LLMの内部の仕組みを解明しようとする研究（Mechanistic Interpretability）も活発になっており、XAIは従来の機械学習モデルにとどまらない、AI全般の課題になっています。

## 4. 代表的な手法

ここでは、実務でよく使われる代表的な手法を紹介します。

### 4-1. Feature Importance（特徴量の重要度）

モデル全体として、どの特徴量（入力項目）をどれだけ重視しているかを示す、最もシンプルな **大域的な説明** です。

勾配ブースティング系のライブラリ（LightGBM、XGBoostなど）には標準で備わっており、手軽に確認できます。ただし、「重要である」ことはわかっても、「値が大きいとリスクが上がるのか下がるのか」まではわかりません。

### 4-2. SHAP

**SHAP（SHapley Additive exPlanations）** は、現在最もよく使われているXAI手法の一つです。

ゲーム理論の「シャープレイ値」という考え方をもとに、**1件の予測結果を、各特徴量の貢献度に分解** します。

たとえば、ある企業の与信リスクスコアが 0.82 と予測された場合、次のように分解できます。

| 特徴量 | 値 | 貢献度 |
|---|---|---|
| ベースライン（全体の平均） | — | 0.30 |
| 直近の延滞回数 | 3回 | **+0.28** |
| 設立年数 | 2年 | +0.15 |
| 自己資本比率 | 12% | +0.12 |
| 従業員数 | 150人 | −0.03 |
| **予測値** | | **0.82** |

「延滞回数の影響が最も大きく、次いで設立からの年数が浅いこと」が、リスクが高いと判定された理由だとわかります。

局所的な説明を全データ分集計すれば、大域的な説明としても使えるのがSHAPの便利なところです。Pythonでは `shap` ライブラリで簡単に試せます。

```python
import shap

explainer = shap.TreeExplainer(model)
shap_values = explainer(X_test)

# 1件の予測の内訳
shap.plots.waterfall(shap_values[0])

# モデル全体の傾向
shap.plots.beeswarm(shap_values)
```

### 4-3. LIME

**LIME（Local Interpretable Model-agnostic Explanations）** は、説明したいデータの周辺で入力を少しずつ変えながら予測結果を観察し、その周辺だけで成り立つ **シンプルなモデル（線形モデルなど）で近似** する手法です。

モデルの種類を問わず使えるのが特徴ですが、入力の変え方によって説明が変わることがあり、結果が安定しにくいという弱点もあります。

### 4-4. Grad-CAM

**Grad-CAM** は、画像分類モデルが **画像のどこを見て判断したか** をヒートマップで可視化する手法です。

先ほどの「狼とハスキー犬」の例のように、モデルが本来見るべき部分を見ているかを、視覚的に確認できます。

### 4-5. 反実仮想説明（Counterfactual Explanation）

**「何がどう変わっていれば、結果が変わったのか」** を示す手法です。

たとえば、ローン審査で否決された人に対して、「年収があと50万円高ければ承認されていました」と示します。

貢献度の数字よりも、判断を受けた本人にとって直感的にわかりやすく、**次に何をすればよいか** まで伝えられるのが強みです。

## 5. ユースケース

ここからは、XAIが実際にどう役立つのかを、4つのユースケースで紹介します。

### 5-1. 金融：与信審査の結果を説明する

AIで融資の可否を判定する場面です。

XAIがない場合、担当者は「AIが否決と判定した」としか伝えられず、顧客から理由を聞かれても答えられません。

XAIがある場合は、SHAPで **「延滞履歴」「借入件数」** が否決の主な要因だったことを示し、反実仮想説明で **「借入件数が1件少なければ承認の可能性があった」** と伝えられます。審査担当者が判断の妥当性を確認したうえで、顧客に根拠を持って説明できます。

### 5-2. 医療：画像診断の根拠を医師が確認する

AIがレントゲン画像から病変の可能性を指摘する場面です。

XAIがない場合、医師はAIの「異常あり」という結果を信じるか信じないかの二択になります。

XAIがある場合は、Grad-CAMで **AIが注目した部位** をヒートマップで示せます。医師は、その部位が医学的に妥当かを確認したうえで最終判断を下せます。もしAIが画像の端にある文字やマーカーに注目していたら、モデルの問題に気づくこともできます。

### 5-3. 製造：異常検知のアラートの原因を特定する

工場のセンサーデータから、設備の異常を検知する場面です。

XAIがない場合、「異常の可能性あり」というアラートが出ても、どこを点検すればよいかわかりません。現場が点検箇所を探し回ることになり、誤検知が続くとアラート自体が無視されるようになります。

XAIがある場合は、**「モーターAの振動」と「冷却水の温度」** の変化がアラートの主な要因だったことを示せます。現場はすぐに点検箇所を絞り込めます。

### 5-4. 営業：AIのスコアを「次の行動」につなげる

AIが顧客ごとに「解約リスク」や「成約見込み」をスコアリングする場面です。

XAIがない場合、営業担当者は「この顧客は解約リスク85%」という数字を見ても、何をすればよいかわかりません。

XAIがある場合は、**「直近3ヶ月のログイン回数の減少」「サポートへの問い合わせ増加」** がスコアを押し上げていることがわかります。担当者は「利用状況のヒアリング」や「サポート状況の確認」など、具体的なアクションにつなげられます。

## 6. XAIを使うときの注意点

XAIは万能ではありません。使うときには、次の点に注意が必要です。

### 6-1. 説明は「因果関係」ではない

SHAPやLIMEが示すのは、**モデルがその特徴量をどう使ったか** であって、**現実世界の因果関係** ではありません。

「ログイン回数が減るとスコアが上がる」というのはモデルの中での話であり、「ログインさせれば解約を防げる」とは限りません。

### 6-2. 手法によって説明が変わることがある

同じモデル・同じデータでも、SHAPとLIMEで異なる説明が出ることがあります。また、相関の強い特徴量が複数ある場合、貢献度が分散したり、どちらかに偏ったりして、解釈が難しくなります。

一つの手法の結果を鵜呑みにせず、複数の手法やドメイン知識と照らし合わせることが大切です。

### 6-3. 「もっともらしい説明」に注意する

特にLLMでは、「なぜその回答をしたのか」を尋ねると、もっともらしい理由を文章で返してくれます。しかし、**その説明が実際の内部の処理を正しく反映しているとは限りません**。

説明がわかりやすいことと、説明が正しいことは別物です。

### 6-4. 説明する相手によって、必要な説明は変わる

| 相手 | 求める説明 |
|---|---|
| データサイエンティスト | モデルが正しく学習できているか（大域的な説明、詳細な数値） |
| 業務担当者 | この1件をどう判断し、どう動けばよいか（局所的な説明、主要な要因） |
| 判断を受けた本人 | なぜこの結果になったのか、どうすれば変わるのか（反実仮想説明） |
| 監査・規制当局 | 判断のプロセスが公平で、記録されているか |

**誰に、何のために説明するのか** を最初に決めることが、XAIを使いこなす第一歩です。

## 7. まとめ

- XAIは、AIの判断の根拠を人間が理解できる形で示すための技術・考え方
- 説明には「モデル全体の傾向（大域的）」と「1件ごとの理由（局所的）」があり、SHAP・LIME・Grad-CAM・反実仮想説明などの手法がある
- AIが人の生活やお金に関わる判断を担うようになり、規制の面でも、モデルの品質管理の面でも重要性が増している
- ただし、説明は因果関係ではなく、手法によって結果が変わることもあるため、鵜呑みにせず使うことが大切

AIを業務で使い続けてもらうためには、精度だけでなく **「納得できること」** が欠かせません。XAIは、AIと人間の間に信頼をつくるための技術です。
